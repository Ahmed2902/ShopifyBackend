# Stride Shopify Web Pixel extension

This directory contains the **Stride-owned collector source** used by PIXEL-1.

The backend repository is not currently a Shopify CLI app project and does not contain a Shopify-generated Web Pixel extension UID. Shopify requires the extension UID to be generated by Shopify CLI, so this repository intentionally does **not** invent one.

## Scaffold in the Shopify app project

From the actual Shopify app project:

```bash
shopify app generate extension --template web_pixel --name stride-pixel
```

Keep the generated `uid` in that extension's `shopify.extension.toml`.

Then:

1. replace the generated extension `src/index.js` with this directory's `src/index.js`;
2. copy the privacy/settings declarations from `shopify.extension.toml.template` while preserving the CLI-generated `uid`;
3. deploy or run the Shopify app version normally;
4. reauthorize existing stores with `write_pixels` and `read_customer_events` if those scopes were not already granted;
5. call Stride's authenticated installation endpoint:

```text
POST /v1/stores/:storeId/pixel/install
```

The backend creates or updates the Shopify `WebPixel` resource with three settings:

```text
collectorUrl
installationId
collectorToken
```

The raw collector token is sent to Shopify as pixel settings but is stored by Stride only as a SHA-256 hash. Re-running installation rotates that credential.

## Runtime behavior

The extension subscribes only to Shopify standard customer events exposed to App Web Pixels. It does not inspect the storefront DOM.

Supported mapping includes:

```text
page_viewed                         -> PAGE_VIEW
product_viewed                      -> PRODUCT_VIEW
collection_viewed                   -> COLLECTION_VIEW
search_submitted                    -> SEARCH
product_added_to_cart               -> ADD_TO_CART
product_removed_from_cart           -> REMOVE_FROM_CART
checkout_started                    -> BEGIN_CHECKOUT
checkout_* / payment progression    -> CHECKOUT_PROGRESS
checkout_completed                  -> CHECKOUT_COMPLETED
```

`SEARCH` records that a search occurred but deliberately does not copy the shopper's raw search string.

The extension:

- respects Shopify's customer-privacy state and sends analytics events only when analytics processing is allowed;
- uses Shopify's event `clientId` only as an opaque anonymous visitor identity;
- creates a session-scoped opaque ID from the first event ID;
- extracts only allowlisted UTM/click-ID parameters;
- strips query strings/fragments/credentials before retaining landing/page URLs;
- batches events and performs bounded retries;
- relies on backend `(storeId,eventId)` uniqueness for durable retry deduplication.

## Verification

Before a merchant beta, verify in a Shopify development store:

1. extension deploy succeeds with the real Shopify-generated UID;
2. the store has granted `write_pixels` + `read_customer_events`;
3. `POST /v1/stores/:storeId/pixel/install` returns `ACTIVE`;
4. `GET /v1/stores/:storeId/pixel/status` exposes the provider pixel ID and event freshness without exposing the raw collector token;
5. storefront navigation/cart/checkout events reach `POST /v1/pixel/events`;
6. duplicate delivery of the same event does not create a second row;
7. denied analytics consent produces no persisted behavioral event;
8. persisted URLs contain no query string;
9. expired raw events are removed by the retention worker.

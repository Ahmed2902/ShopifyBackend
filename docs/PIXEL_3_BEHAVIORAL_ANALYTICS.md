# PIXEL-3 — Behavioral analytics

PIXEL-3 converts the privacy-bounded session/journey read model from PIXEL-2 into durable, non-pseudonymous daily behavioral facts.

## Truth boundary

Behavioral metrics are Stride first-party observations. They do not replace Shopify commerce truth or Meta provider attribution.

A purchase metric is counted only when a Pixel session has an exact Shopify order identity linked to a Stride `Order` that is not a test order and is not cancelled. Product purchase metrics additionally require the linked Shopify order to contain the observed product/variant.

No fuzzy timestamp, price, customer, or SKU-nearby matching is used.

## Privacy model

`StorefrontBehaviorDaily` never stores visitor IDs, browser session IDs, checkout tokens, click IDs, or ad identifiers. It stores daily aggregate counts by:

- store
- product
- collection
- sanitized landing page

Raw events and materialized pseudonymous sessions continue to expire according to the Pixel retention policy. Daily aggregate facts may remain after those traces are deleted.

## Session cohort semantics

A session is assigned to the store-local calendar date on which it started. All metrics generated by that session are assigned to that date. This keeps daily rollups deterministic even after the underlying session trace expires.

## Metrics

Store/landing-page metrics include:

- sessions
- page/product/collection views
- searches
- add/remove-cart events
- product-view sessions
- add-to-cart sessions
- checkout-start/completed sessions
- exact Shopify-linked purchase sessions
- session-to-purchase delay

Product metrics include:

- interacting sessions
- product views
- product-view sessions
- add/remove-cart events
- add-to-cart sessions
- checkout progression after product interaction
- exact Shopify-linked product purchase sessions
- view-to-cart, cart-to-purchase, and session-purchase rates
- identity resolution quality

Collection purchase counts are explicitly downstream same-session Shopify purchase evidence. They are not causal collection attribution.

## APIs

Authenticated store members can read:

- `GET /v1/stores/:storeId/pixel/analytics/overview`
- `GET /v1/stores/:storeId/pixel/analytics/products`
- `GET /v1/stores/:storeId/pixel/analytics/collections`
- `GET /v1/stores/:storeId/pixel/analytics/landing-pages`

The APIs reuse Stride's normal store-timezone date contract and equal preceding comparison period.

## Eventual correctness

The collector remains optimized for durable event capture. PIXEL-2 materializes sessions, then the PIXEL-3 worker finds session read-model updates newer than its per-store watermark. This includes both new/repaired materializations and a later `PENDING -> LINKED` Shopify-order repair. It rebuilds every affected store-local date from the complete retained session set before advancing the watermark.

Late events, repaired sessions, and late exact Shopify order links therefore replace a daily aggregate deterministically rather than incrementing it twice or leaving purchase metrics stale.

The behavior rollup worker runs before Pixel trace-retention cleanup.
